## [0.1.22] - 2026-11-05

主题：**语音输入（2a）——说一句，识别结果只进草稿**。

设计稿：`.scratch/alignment/2026-11-05T2023-语音输入与搜索设计.md`。
拍板：结果只进草稿 / 语音搜索下一版做（直接填并立即筛）/ provider 不可用时禁用 + 说明。

### 新增

- **宿主语音桥**（`lib/index.js`，第一次用上宿主半侧）：按 dsh-prompt 的先例用
  `ctx.webServer.register` 挂 `/_dsh/dsh-sticky-notes/voice/*` 前缀路由——
  `GET …/voice/catalog` 返回 provider 可用性/语言/上限，`POST …/voice/transcribe` 收
  base64 WAV 并转发给 DSH 的 `speechToText`。只接受 loopback Host；校验 canonical base64、
  2MB / 60 秒上限与 WAV 头；音频只在内存里走一趟，不落盘、不写日志内容。
- **浏览器录音**：`getUserMedia` + `MediaRecorder` → `decodeAudioData` →
  `OfflineAudioContext(16kHz 单声道)` 重采样 → 自己编码 PCM16 WAV → base64 →
  同源 `fetch` 桥。录音上限 60 秒，到点自动停止。
- **入口与渐进披露**：`⋯` 菜单新增「语音记一条」（低频入口）；成功用过一次后，草稿框底部
  才出现麦克风（用 `voice` 埋点判断，不新增 localStorage key）。录音/转写期间显示一行状态
  （录音中 · 计时 / 转写中…）+ 停止按钮，结束即消失。
- **失败态分开**：无麦克风权限 / 找不到设备 / 环境不支持 / 转写失败 / 没听清 / 录音超长 /
  音频格式错 / 语音服务未启用 / provider 不是本机 / 模型未就绪——各一句人话。
- **provider 硬闸门**：只有 `location === 'host-local'` 且 `preparation === 'ready'` 才放行；
  云端 provider 或模型未就绪时入口 disabled + `title` 说明，**不在面板里触发模型下载**。
- **只进草稿、不自动提交**：识别文本进草稿（草稿框有焦点时插光标处，否则追加末尾），
  用户检查/修改后自己 `Ctrl+Enter`。`Esc` 取消录音/转写并释放麦克风；关面板同样取消。

### 变更

- README 的隐私承诺改写：从「不经 Host、不发网络请求」改成
  「便签正文只存本机 localStorage；语音识别在本机 Host 进程内完成，音频只在内存里走一趟、
  转写完即丢，不上报、不联网」。
- `METRIC_KEYS` 新增 `voice` 计数（导出 Markdown 的本机统计里会多一行）。
- `scripts/check.mjs` 的测试清单加入 `host.mjs`；插件 `npm test` 一起跑宿主桥单测。

### 测试

- **新增 `test/host.mjs`**：路由注册形态、catalog 的四种不可用原因、transcribe 成功与
  输入校验（非法 base64 / 非 WAV / 超时长 / 超大小）、转写失败与空结果、非 loopback 403、未知路由 404。
- **`test/behavior.mjs` 新增「语音输入」组**：打开面板读 catalog、菜单入口与禁用态、
  录音 → 停止 → 转写 → 文本进草稿且不提交、上送的是 RIFF WAV、权限拒绝提示、
  云端 provider 禁用 + title、Esc 取消释放麦克风且不发转写请求、语音计数 +1。
  测试台补了假 `getUserMedia` / `MediaRecorder` / `AudioContext` / `OfflineAudioContext` /
  `fetch` / `btoa`。
- **`test/smoke.mjs` 新增 2 条样式断言**（录音状态行、草稿框语音按钮）。

- 归档便签仍只读（拍板）：先恢复再改，不把「归档」语义改成「换个视图」。

## [0.1.20] - 2026-11-05

主题：**正在打的字、粘进来的 emoji 都不再丢；记一条不再重画整个列表**。

这一版来自一次全量审计：下面三处都是「看起来能用」、但真触发时会丢内容或打断输入的问题，
再加一个用测试钉住渲染次数的性能优化。零新增 note 字段、零新增 localStorage key、备份格式不变。

### 修复

- **多标签页同步不再冲掉本页正在打的内容**（数据丢失）：本页有还没落盘的改动时（300ms 去抖窗口内），
  另一页落盘触发的 `storage` 事件以前会整份替换 `store.notes`，本页刚打的字连同落盘定时器一起消失。
  现在按 id 合并（`mergeIncomingNotes`）：本页动过的保留、另一页改过的采用、另一页新增的收进来、
  另一页删掉的跟着删，本页刚删掉的不被另一页的快照复活。判断「哪些 id 还没落盘」用的是
  `lastSavedNotes`（上次成功落盘的快照），落盘定时器回调里顺手把 `saveTimer` 归零。
  同一 id 两边同时改仍然是「后落盘的赢」，和原来的整份覆盖语义一致。
- **剪贴板清洗不再删 ZWJ / ZWNJ**（改写用户文字）：`👨‍👩‍👧` 里的 ZWJ（U+200D）、
  波斯语/印地语单词里的 ZWNJ（U+200C）是语义连接符，不是零宽垃圾。之前 `cleanClipText`
  把它们和 ZWSP / BOM 一起删掉，粘进来就被改写；现在只清 ZWSP / BOM，其余原样保留。
- **输入法组词中按 Esc 不再收起面板 / 清搜索词**：`Esc` 分层退出没有组词判定，
  中文/日文输入法按 Esc 取消候选会被当成「退出」——搜索态下先清搜索词，无搜索词时整个面板收起。
  现在 `event.isComposing || event.keyCode === 229` 时直接放行（Safari 常在 `compositionend`
  之后才发结束组词的那次 keydown，所以不能只判 `isComposing`），和草稿框 `Ctrl+Enter` 同一道判定。

### 优化

- **`tick` 不再进卡片 props**：父组件把相对时间算成 `timeText` 字符串传下去。
  以前 30 秒心跳、以及每次「记下」（`addNote` / 从剪贴板成卡里的 `setTick(now)`）都会让
  `memo(NoteCard)` 全部失效——300 条时按一次「记下」要白画 301 张卡、30 秒心跳要白画 300 张。
  现在「记下」只重画新加的那一张，心跳只重画时间文案真的变了的那几张（通常 0 张）。

### 测试

- 行为测试新增：多标签页同步（未落盘编辑保留 / 别处新增与修改收进来 / 本页删除不复活 /
  本页干净时整份采用）、剪贴板内容保真（ZWJ + ZWNJ 保留 / ZWSP + BOM 仍清）、
  渲染次数（记下一条只重画新卡 / 30 秒心跳不重画未变卡片）、输入法 Esc 放行（有搜索词与无搜索词两条路径）。
  测试台补了三件能力：`storage` 事件派发、虚拟 `setInterval`（30 秒心跳）、
  以及跟着虚拟时钟走的 `Date.now()`（否则「打开一会儿再记下」测不出来）。
- 反验过：把 `lib/client.js` 换回 0.1.19 再跑，上面 14 条新断言全红
  （多标签页 4、emoji 2、渲染次数 2、Esc 3，另 3 条是 Esc 链被连累的下游断言）；
  换回本版后全绿。

## [0.1.19] - 2026-11-04

主题：**复制出来的东西，一步变成便签**。捕获通道的第一个入口：剪贴板。

### 新增

- **从剪贴板直接记下（快捷档）**：面板打开时，焦点不在输入框里按 `Ctrl/Cmd + V`，
  剪贴板文本直接成一条便签（落最上面、颜色「未排」、记当前会话），toast 带前 30 字预览，
  5 秒内可整条撤销。焦点在任何输入框里时完全不拦——原生粘贴照旧。
- **从剪贴板记下（安全档）**：`⋯` 菜单新增一项，读剪贴板后**只填进草稿**、不建卡，
  用户看一眼再 `Ctrl+Enter`。防的是「复制了密码/私钥，顺手点一下」直接落盘。
- **内容清洗与边界**：去首尾空白、CRLF 归一、零宽字符清理，内部换行保留；
  空剪贴板、读不到剪贴板各有明确文案与退路；与已有便签完全重复时不新增，
  滚到那条闪一下并提示「这条已经在列表里」；2000–8000 字自动退草稿，>8000 字拒绝。
- **长度分布埋点**：`METRIC_KEYS` 增加 `clipboard` 与三档长度计数（≤20 / 21–80 / >80 字），
  只记桶不记内容——长便签占比是决定「要不要做语音输入」的唯一硬证据。

### 设计

- **不做全局 `paste` 监听、不做后台轮询**：只由用户显式动作触发一次读取。
  否则用户往聊天框粘 API key 时会被顺手抄进便签，再进备份和 Markdown 导出。
- 两种入口的差别就是「我知道剪贴板里是什么」与「我不确定」：前者要快，后者要能反悔。
- 零新增 note 字段、零新增 localStorage key：重复检查用内存里的当前列表，不写 hash 字段。

### 测试

- 行为测试新增「剪贴板捕获」一组：快捷档成卡 + 清洗 + 预览 + 5 秒撤销、输入框内不接管、
  重复不新增、超长拒绝、长内容进草稿、菜单档只填草稿且需 `Ctrl+Enter` 才落盘、
  读不到 / 空剪贴板各有提示、`clipboard` 与长度桶计数。
- 反验过：去掉焦点判定、去掉重复检查、去掉超长拒绝、把菜单档改成直接建卡——对应断言立刻失败。

## [0.1.18] - 2026-11-04

主题：**颜色变成「重要程度」，并把调研里欠的三件 P0 补上**。

### 新增 / 变更

- **颜色 = 重要程度 5 档**（你拍板的方案）：1 最要紧 → 4 靠后，**5「未排」是默认档**。
  色板里带档位数字与名字（1 最要紧 / 2 要紧 / 3 一般 / 4 靠后 / 5 未排），按档位筛选的菜单同样按这个顺序。
  数据模型零改动：颜色仍是原来的字符串，语义是视图层的固定映射，老备份原样能用。
- **新便签不再随机取色**：默认落在「未排」。系统不替你排优先级——没想清楚就先不排。
- **不用颜色也能读到档位**：色点右侧显示档位数字（「未排」不显示数字，不假装有优先级），
  加上色板文字、筛选菜单文字与 `aria-label`，三处冗余（WCAG 1.4.1）。
- **换色埋点**：`METRIC_KEYS` 增加 `color`，Markdown 导出里的本机统计会带上「换色 N 次」。
- **浅色主题五色压深一档**：`#c93a5e / #b8780a / #1d8a5b / #1f6fd6 / #6f52d9`，
  对卡片底 3.36–4.96:1（原来 1.73–2.76:1，低于图形元素 3:1）；深色主题保持原来那套（5.19–7.55:1）。
- **五色进对比度门禁**：`npm run contrast` 现在从 `lib/client.js` 里解析这五个色值逐对算比值，
  改色忘改测试会直接红。

### 注意

- **老便签的颜色不迁移**：0.1.17 之前颜色是随机分配的，没有信息可还原；做「一键归为未排」等于删你的数据，
  所以不做。老便签保持原色、被读成对应档位，想重排点一下色点即可。

### 测试

- 行为测试：默认色是「未排」（连建两条都断言）、「未排」不显示档位数字、有档位显示数字、
  换色会计一次数、色板按档位排序并带数字、按档位筛、与 `#标签` 是「且」、`Esc` 逐层退出。
- 对比度测试新增 5 色 × 浅/深 = 10 对，全部 ≥ 3。
- 反验过：默认色改回别的档 / 去掉换色打点 / 浅色色值退回旧的亮色——三处都会让对应测试失败（对比度直接 ✗）。

## [0.1.17] - 2026-11-04

主题：**颜色从装饰变成能用的分类通道**。调研 P1 的两项一起做：具名调色板 + 颜色即检索。

### 新增

- **具名调色板**：点卡片右下角的色点，在卡片内联展开 5 个色块 + 色名（琥珀/天蓝/薄荷/玫瑰/紫罗兰），
  点一下就换成目标色——不再「点一下循环、到目标色要试 2-4 次」。当前色有环标和 `aria-pressed`。
- **颜色即检索**：搜索框左侧多了一个色点触发器，点开是「全部颜色 + 5 色」并带**各色条数**
  （按当前搜索词算、不叠加颜色条件，所以能看出「选了会剩几条」）；选中后触发器变成「色点 + 色名」。
- 颜色筛选与 `#标签` / 关键词是**「且」**：`#想法` + 玫瑰 = 带该标签且是玫瑰色。有颜色筛选时
  列表同样覆盖全部（含归档），视图芯片同步高亮「全部」。
- `Esc` 链补了一层：菜单 → 卡片调色板 → 颜色菜单 → 搜索词 → 颜色筛选 → 收起面板。

### 设计

- **色名是必需的，不是装饰**：颜色不能作为唯一信息通道（WCAG 1.4.1）。所以色点的 `aria-label`
  是「颜色：薄荷（选择颜色）」，色板和菜单里每一项都带文字名。
- 调色板**内联展开而不是浮层**：300px 面板里浮层会被列表滚动裁掉、还得算翻方向；内联只让那张卡片长高一行。
- 给 memo 卡片的约束照旧：只有「正在选色的那张」才多两个 prop，其余卡片 props 形状不变
  （`test/perf.mjs` 300 条稳态 0.28-0.42ms、`cardsSteady: 0`）。
- 颜色筛选器放在搜索框里（不另起一排常驻图例），首屏仍然留给列表。

### 测试

- 行为测试新增「颜色」一组：色板 5 色 + 色名 + 当前色标记、选色落盘且不改 `updatedAt`、

- **拿不到会话就自动降级**：如果 slot 没送来标准 kit（或版本换代后接口变了），
  「本会话」标签不出现，便签栏仍是一个纯本地便签工具——不会残一个点了没反应的按钮。
- 老便签没有 `sessionId`，只出现在「全部」里，**不强制迁移**。

### 实现要点

- slot 注册的组件现在会被转发整套标准 props（`Object.assign({}, slotProps, { locale })`）；
  之前只取了 `locale`，把 `useSessions` 这类 selector hook 丢掉了。
- 「当前会话」用官方同一套判据：`useSessions(state => Object.values(state.byId)
  .find(s => (s.retainedBy.mainView ?? 0) > 0)?.id)`——与 `dsh-client-ui-layout` 的
  `DocumentTitle` 完全一致（该结论来自读 0.2.1-rc.2 的 client bundle）。
- hook 顺序稳定：有 kit 时调 kit 的 selector hook，没有时退回 `useState(null)`，
  两条分支都只占一个 hook 槽位。

### 测试

`test/behavior.mjs` 用模拟 kit（`useSessions` 返回可切换的会话快照）断言：新便签记下当前会话、
切会话后新便签换 id、切回来自动更新「本会话」视图、计数正确、无 kit 时只有 2 个标签。

## [0.1.5] - 2026-11-04

主题：**先量再改**。列表最多 500 条，之前每敲一个字都会把整张列表重渲染一遍。

### 性能

- **卡片 memo 化**：`NoteCard` 改成 `memo(NoteCard)`，并把 `t` / `timeLabels` / 7 个回调
  （更新、落盘、换色、置顶、归档、恢复、删除）全部 `useMemo` / `useCallback` 稳住引用，
  否则浅比较每次都会失败、memo 形同虚设。回调不再闭包 `store`，需要「当前列表」时读
  `latestStore` ref。
- 结果：打字时**只有正在编辑的那 1 张卡片重渲染**，其余按 props 跳过。

同一套测法（`test/perf.mjs`，假 React 里 `memo`/`useMemo`/`useCallback` 有真语义）改前改后对比：

| 便签数 | 一次重渲染构造的元素 | 一次重渲染耗时 |
|---|---|---|
| 100 | 2053 → **50** | 0.56ms → **0.10ms** |
| 300 | 6053 → **50** | 1.62ms → **0.21ms** |
| 500 | 10053 → **50** | 3.42ms → **0.35ms** |

诚实的边界：这是 Node 里量「构造 JSX 元素」的成本，**没有量浏览器端的 DOM diff/commit**；
真实打字成本 = 父组件 + 1 张卡片，所以上表是下限收益，不是浏览器里的绝对耗时。

### 测试

- 新增 `test/perf.mjs`（`npm run perf`）：可用第二个参数指定客户端文件路径，直接对比任意两个版本。
- `test/behavior.mjs` 的迷你 React 补上 `memo` / `useMemo` / `useCallback` 的真语义，
  并断言「打字只重渲染 1 张卡片」——去掉 memo 这条会立刻失败。

## [0.1.2] - 2026-11-04

「用着用着才会发现」的三个问题，都是一行到十行级别的改动，但直接影响手感。

### 修复

- **编辑时卡片不再跳到列表顶部**：原先每次按键都把 `updatedAt` 刷成当前时间，

## [0.1.0] - 2026-11-04

首个公开版本。三轮迭代（P0/P1/P2）合并为一次发布。

### 新增

- 左侧便签栏：会话列表右边缘的竖排「便签」标签，点开为 300px 抽屉；`Alt + Shift + N` 全局开关。
- 快速记录：`Ctrl/Cmd + Enter` 记下；每条便签可原地编辑、换色、置顶、删除、归档。
- 搜索：便签 ≥ 6 条时出现搜索框，`Ctrl/Cmd + K` 聚焦，`Esc` 先清搜索再收起。
- 撤销：删除后 5 秒内可撤销（`aria-live` 提示），替代「点两次确认」。
- 归档：归档 / 恢复 + 「全部 / 已归档」过滤，归档便签置灰只读。
- 导出：全部便签导出为 Markdown，文末附本机使用统计。
- i18n：接入 DSH locale（zh / en，其余语言按 en 回退），语言切换即时生效。
- 本机埋点：打开 / 新建 / 编辑 / 删除 / 撤销 / 置顶 / 归档 / 恢复 / 导出 / 搜索。

### 可用性

- 命中区：换色按钮 24×24、删除 28×28、头部图标 32×32，均达 WCAG 2.2 AA 24px 底线。
- 对比度：暗色主题下品牌按钮由「白底白字 1.05:1」修正为反色文字 15.03:1；提示文字 / 时间戳浅色 5.80、深色 10.42。
- 遮挡：面板贴在会话列表右边界展开（量 `[data-dsh-sidebar-root]` + `ResizeObserver`），不再遮挡会话列表，且移除全屏遮罩。
- 图标：换用 DSH primitives 的 Fluent 图标，取不到时回退手绘 SVG。

### 说明

- 数据只存本机 localStorage，不经 Host、不上报。
- 兼容性只在此版本实测过 DSH `0.2.1-rc.2`。
