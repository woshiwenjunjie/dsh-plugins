# 捕获通道：语音输入 + 复制快速记录（功能设想 v2）

> 状态：设想稿 v3——**P0 已落地（0.1.19）**：剪贴板快捷档（面板空白处 `Ctrl+V` 直接成便签、5 秒撤销）
> + 安全档（`⋯` 菜单只填草稿）+ 长度分布埋点。语音仍未动，等 §11 的两个验证。
> 问题在文末「需要你拍板」。
> 反方评审见 [critique.md](critique.md)（独立智能体产出，**结论与本文有分歧，保留**）。
> v2 修订：吸收了反方评审的三条硬意见——不做全局 paste 监听、语音入口不常驻、剪贴板要留「先看后交」的安全档。

## 术语对齐（我按这个理解做设想，错了请纠正）

| 你说的 | 我理解的 | 不是这个意思（本设想不做） |
| --- | --- | --- |
| 复制快速记录 | **剪贴板内容 → 便签**，不经过「粘贴到草稿再删」 | 不是「把便签复制成文字」，也不是「复制一条已有便签」 |
| 语音输入 | **说话 → 识别成可编辑文本 → 进便签** | 不是「录一段音频存成便签」——那要新增附件存储、备份格式、播放 UI，成本完全不同 |

## 一句话结论

便签下一步不是加功能，是**降低「内容已经在手边」的捕获成本**：把「拿（剪贴板）」和「说（语音）」接成同一条捕获通道。
**剪贴板现在做**（半天、零外部依赖、高频）；**语音先不做、先验证两件免费的事**（系统听写是否已覆盖；长便签占比够不够），
若做则入口收进 `⋯`、只用本机识别、结果只进草稿。

### 反方结论速览（保留分歧）

| 判断 | 本文 v2 | 反方 critique.md |
| --- | --- | --- |

| 全局 `paste` 监听 | 不做（写死） | 不做（写死）——**这条两边完全一致** |

## 0. 问题：捕获一条便签，现在要几步

现状（0.1.18）：`Alt+Shift+N` 打开面板（**焦点已在草稿框**）→ 打字 → `Ctrl+Enter`。**打字是最贵的一步**。

| 瞬间 | 现在 | 想要 |
| --- | --- | --- |
| 会话里看到一段结论，已经选中复制 | 开面板 → 点草稿框 → `Ctrl+V` → 删多余行 → `Ctrl+Enter` | 一次动作落一条，可撤销 |
| 网页/终端里复制一段报错，想顺手记下 | 同上，还要处理粘贴格式 | 面板里 `Ctrl+V` 直接成便签（或填草稿） |
| 躺下/走路想到一个点子，不想打字 | 打不了 / 太慢 | 说一句，识别成文本进草稿可改 |

**反例（不成立的场景，要先认）**：剪贴板里是密码/私钥/token（热键抓取会出事）；焦点正在输入框里打字（`Ctrl+V` 必须原生粘贴）；
想存一整篇文档（便签不是剪藏）；想要会议纪要（语音输入不是转写工具）。

## 1. 统一模型：一条捕获通道

```
键盘打字 ─┐
剪贴板   ─┼→ 成稿（草稿 / 直接落盘）→ 确认（Ctrl+Enter 或 5 秒撤销窗）→ notes
语音     ─┘
```

三条规则：
1. **语音结果只进草稿，绝不直接建卡**：识别一定会错，且半句话/错句一旦落盘会进列表、进回顾条。
2. **剪贴板分两档**：快捷姿势 → 直接成便签（快，5 秒撤销）；菜单入口 → 填草稿（先看后交，敏感内容兜底）。
3. **只读一次、不驻留、不监听**：由用户显式动作触发；音频不存、剪贴板不留、日志不记内容。

## 2. 功能一：复制快速记录（剪贴板捕获）

### 2.1 两个入口，两种行为（v2 的关键修订）

| 入口 | 行为 | 为什么 |
| --- | --- | --- |
| 面板内「空白处 `Ctrl+V`」（焦点不在输入框） | **直接成一条便签** + toast 带前 30 字预览 + 5 秒撤销 | 这是「我知道我刚复制了什么」的姿势，图的就是少一步 |
| `⋯` 菜单「从剪贴板记下」 | **填进草稿**（不提交），用户看一眼再 `Ctrl+Enter` | 这是「我不确定剪贴板里是什么」的姿势；密码/私钥不会因为一次误点直接落盘 |
| `Alt+Shift+V`（P1） | 同「直接成便签」 | 与 `Alt+Shift+N` 同族；先看误触率 |

焦点规则（最容易回归的地方，必须有断言）：
- `event.target` / `activeElement` 是 input、textarea、contenteditable → **完全交给原生粘贴**，不拦截；
- 其它情况且面板打开 → 捕获；面板收起时只有 `Alt+Shift+V` 才捕获。
- **禁止**全局 `paste` 监听：用户往聊天框粘 API key 时也会被抄进便签（反方评审的第一硬禁止，我完全同意）。

### 2.2 清洗与分岔

- `trim()`、去首尾空行、`\r\n → \n`、去零宽字符；内部换行保留。
- 空 / 只有空白 → toast「剪贴板里没有文字」（现状 `addNote` 对空串静默 return，不能让它表现为「按钮坏了」）。
- 读失败（权限拒绝、不稳定上下文、不支持）→ toast「读不到剪贴板，可以点输入框按 `Ctrl+V`」——**给退路**。
- 长度（上限待定，见第 12 节）：≤ 2000 字符正常处理；2001–8000 → 两档都改为「进草稿并提示有点长」；\> 8000 → 拒绝并说明「便签不是剪藏」。
- 富文本/图片：只取 `text/plain`；没有文本 → 「剪贴板里没有文字」。
- 重复：与现有便签规范化后全等 → 不新增，滚动到那条并高亮 1.5 秒 + toast「这条已经在列表里」。

### 2.3 落盘后的行为（直接成便签档）

- 颜色「未排」、不置顶、`order` 落顶（与新建一致）、`sessionId` = 当前会话。
- 复用现有 `undoState` 通道：toast「已记下：xxx…｜撤销」，5 秒可整条撤销。
- `METRIC_KEYS` 加 `clipboard`（只加 key，不新增 note 字段）。

### 2.4 隐私与风险

- 只在用户动作后读**一次**；不轮询、不监听、不发网络。
- 读到内容只进便签正文：不写日志、不进埋点。
- **敏感内容**：`⋯` 菜单的「先看后交」档就是为此；快捷档靠「前 30 字预览 + 5 秒撤销」兜底。不做启发式敏感词检测（误报比风险更烦）。

## 3. 功能二：语音输入

### 3.1 当前判断：先验证，不急着做

反方评审的核心反驳我接受了一半：**「说 15 个字」这个动作撑不起 239MB 下载 + 状态机 + 改稿成本**。
所以在动工前先做两件**几乎免费**的验证：

| 验证 | 方法 | 若成立 |
| --- | --- | --- |
| ① 系统听写是否已覆盖草稿框 | 在便签草稿框聚焦时按 `Win+H`，说一句话 | 插件语音的增量只剩「没装系统语言包的用户」→ 更不值得做 |
| ② 长便签占比够不够 | `METRIC_KEYS` 先加长度分桶计数（不新增 note 字段），观察 2 周 | ≥80 字的长便签占比 < 15% → 不做语音 |

（① 我没实测过，反方评审也标了「尚未实测」——它是这套判断里最便宜的证伪点，建议你先花 5 分钟试。）

### 3.2 如果做，形态是「瘦版」

- **入口**：默认收进 `⋯` 菜单（「语音记一条」）；用户用过 ≥ 1 次后，才在草稿框 foot 显示 24px 麦克风（**渐进披露**，与「搜索 ≥ 6 条才出现」同一套规矩）。
  理由：本插件所有低频能力都收在 `⋯`，语音是「每 200 次记录用 1 次」的入口，不该常驻首屏。
- **手势**：点击开始 / 点击结束（不做长按，避免与点击互判）；`Esc`、点面板外、关面板、切标签页 = 取消并**释放麦克风**。
- **状态机**：`idle → recording（展开一行：电平 + 计时 + 停止）→ transcribing（转写中…）→ 文本插入草稿光标处`；**不自动提交**。
- **上限**：`catalog.maxDurationSeconds` / `maxAudioBytes` 取小，便签自定 **60 秒**，到点自动停止并转写；早前也留可见计时。
- **失败态分开**：无麦克风 / 权限拒绝 / 语音服务未启用 / 模型未准备 / 转写失败 / 没听清（空结果）——各一句人话 + 重试/取消。
- **首次准备**：`unprepared` 时**不在面板里就地下载**（反方意见：触屏误点就下 239MB 不可接受），只显示说明 + 去设置/取消；本机模型已存在（228.2MB int8 + 1.7MB VAD）。
- **隐私硬闸门**：只允许 `location === 'host-local'` 的 provider；若选的是 cloud → 按钮 disabled + 一句「便签承诺只在本机识别」。
- **不存音频**：转写完即丢，不写 localStorage、不进备份、不进日志。

### 3.3 与官方语音输入、README 承诺的关系

- DSH 聊天框已有官方语音（同一套 host 语音服务）；本插件不重复造模型，只复用管线，两处入口各服务各自的输入框。
- **README 那句话要改**：现在写的是「不经 Host、不上报、不发网络请求」。语音走 host 处理器，严格说「经 Host」了。
  若做语音，必须改成「不上报、不联网；音频只在本机进程内转写、转写完即丢弃」，并在插件设置里说清。**这句不改就是假话**——反方这条我认同。

## 4. 技术路径（已核实的事实）

| 事实 | 证据 |
| --- | --- |
| profile 已启用官方语音包 | `profiles/web/package.json` 的 `dsh.profile.bundles` 含 `@deepseek-ai/dsh-experimental-voice-input-bundle` |
| 本机模型已存在 | `harness/speech-to-text/sensevoice/models/sensevoice-onnx/model.int8.onnx`（228.2MB）+ `silero_vad.onnx`（1.7MB）+ tokens |
| host 语音服务 | `speechToText`：`resolve(request)` / `transcribe(spec, signal)` → `Transcript{text, audioSeconds, inferenceSeconds}`；`SpeechInput{audio, language}` |
| 给浏览器的 Remote | `speechController`：`catalog()` / `follow()` / `configure()` / `prepare(id)` / `cancelPreparation(id)` / `transcribe({audioBase64,…})`；catalog 带 `maxAudioBytes`、`maxDurationSeconds`、provider 的 `preparation/languages/setupEstimate` |
| 官方客户端实现 | `MediaRecorder` + `getUserMedia({audio:{echoCancellation,noiseSuppression}})` → `ctx.remote.speech.transcribe(...)` → `inputActions.insertText`；`inject: ['remote','slots','locale','pluginNavigation']` |
| 第三方没有 `ctx.remote` 先例 | `dsh-prompt` 宿主注释：不用 `ctx.remote.*`，走 HTTP 桥，因为「第三方同包 Remote 最小例子未有 profile 内先例」 |
| 有 HTTP 桥先例 | `ctx.webServer.register({kind:'prefix', path:'/_dsh/<plugin>'})` + 同源 `fetch`（dsh-prompt / usage-panel / vision-router） |
| host 读不到系统剪贴板 | host 侧包无任何 `require('electron')` → 剪贴板只能走浏览器 API |
| 浏览器能读剪贴板 | DSH 自家 Excel 预览已用 `navigator.clipboard.readText()`；仍需处理拒绝 |
| 不能用 Web Speech API | Electron 不带 Google 语音服务；官方因此自带本地 SenseVoice |

### 4.1 语音实现路径

- **A（推荐）HTTP 桥**：client 录音 → base64 → `POST /_dsh/dsh-sticky-notes/voice/transcribe` → host `ctx.get('speechToText')` → `{text}`；另有 `GET …/voice/catalog` 给按钮可用性与准备状态。先例足、改动集中在 host 半侧（现在是空插件）。
- **B（更短，需 spike）** `ctx.get('remote')?.speech`：第三方能否直接拿聚合 Remote 未验证、无先例。
- C 自研/内嵌 STT：拒绝。

### 4.2 剪贴板实现

- `navigator.clipboard.readText()`；失败退路 = 引导手动 `Ctrl+V`；当前 GUI 为 `http://127.0.0.1:43129`（Chromium 视为可信来源）。

### 4.3 动工前的三个 15 分钟 spike

| # | 验证 | 成功标准 | 失败就改走 |
| --- | --- | --- | --- |
| 1 | `ctx.get('remote')?.speech` 是否存在 | 能取到 catalog / transcribe | 走 HTTP 桥（A） |
| 2 | 桥能否回环：client `fetch('/_dsh/dsh-sticky-notes/ping')` → host JSON | 200 + JSON，不影响现有路由 | 修注册形态，或退回 Remote |
| 3 | `navigator.clipboard.readText()` 在 GUI 两种手势下能否读到 | 返回文本 | 剪贴板降级为「提示用户手动粘贴」 |

（①② 只有做语音才需要；③ 是剪贴板 P0 的前置。）

## 5. 数据与兼容（不新增 note 字段）

- `note` 保持 10 个字段；剪贴板/语音只写 `text`；颜色「未排」、不置顶、`order` 落顶、`sessionId` 当前会话。
- 7 处手写白名单、备份/合并、多标签页 300ms 整份写回都不受影响（没有新字段可被吞）。
- `METRIC_KEYS` 只加计数：`clipboard`、`voice`，以及（若做语音验证）长度分桶计数。
- 容量：localStorage 约 5MB/源；`MAX_NOTES=500` 只限条数不限字节。500 × 2000 字符 ≈ 100 万 UTF-16 字符 ≈ 2MB，安全；若放到 8000 字符，极端情况会顶到配额 → 建议 2000 字符硬上限。

## 6. UI 形态与首屏成本（300px 里怎么放）

面板实测固定吃掉约 **298px**（头 56 + 草稿 130 + 筛选 34 + 搜索 40 + 回顾条 38），900px 视口下列表剩约 600px ≈ **7 张卡**；750px 笔记本只剩 ≈ **5 张**（数字来自反方评审实测）。

```
┌─ 草稿框（3 行）────────────────────┐
│ 想到什么记什么…                    │
└────────────────────────────────────┘
 已保存              [粘贴]  [＋ 记下]
```

| 新增形态 | 像素成本 | 首屏影响 | 结论 |
| --- | --- | --- | --- |
| 剪贴板按钮塞进 `dsn-composer-foot` | **+0px** | 无 | 做；272px 里要防长文案把提示挤成两行 |
| 语音麦克风常驻 foot | +0px | 无像素，但占了「每 200 次用 1 次」的位置 | **不做常驻**；改 `⋯` 菜单 + 用过一次后渐进出现 |
| 独立录音行（电平 + 计时 + 停止） | +44~56px ≈ 0.6 张卡 | 7 → 6 | 只在录音期间存在，可接受 |
| 首次下载提示行 | +40~60px | 7 → 5 | 不在面板里做；跳设置 |

- 剪贴板：`⋯` 菜单 + 隐形 `Ctrl+V`，**不占布局**。
- 可达性：图标按钮 ≥24px、`aria-label` 明确；录音中 `role="status"`、转写中 `aria-live="polite"`、失败 `role="alert"`；不新增色值（不碰对比度门禁）。
- i18n：中英字典各加约 12 条（含全部错误文案；英文长文案要允许 `dsn-hint` 换行）。

## 7. 测试策略（不依赖真麦克风）

行为测试台已支持假 `navigator.clipboard`、虚拟时钟、`window` 键派发；本次再加 fake `getUserMedia` / `MediaRecorder` / `fetch`。

- 剪贴板断言：编辑区内不劫持、空白提示、超长进草稿、重复高亮不新增、直接档 5 秒撤销恢复、菜单档只填草稿不提交、metrics 计数 +1。
- 语音断言（若做）：点麦克风→录音→停止→转写中→文本插入光标处且**未提交**；权限拒绝提示；provider 未就绪显示准备行而非下载；转写失败可重试；`Esc`/点外面取消后无残留录音；cloud provider 时按钮 disabled。
- 反验（改坏必红）：去掉焦点判定、去掉「只许 host-local」、语音结果自动提交、去掉撤销。
- 手动清单：真麦克风一次；撤销系统麦克风授权一次；禁用语音包一次（入口应消失）；`Win+H` 系统听写一次。
- 性能：不在卡片渲染热路径；300 条稳态应保持 ≤0.3ms、`cardsSteady: 0`。

## 9. 风险与反方（详见 critique.md）

1. **语音可能「听着酷、用着慢」**：说 100 字/分钟，改错比打字更费；且短便签里错一个专有名词要整句重打。
2. **239MB 首次下载是劝退点**：且 toast 最长 4 秒，装不下几分钟的下载进度 → 提示必须用常驻行，或干脆跳设置。
3. **隐私承诺**：「不经 Host」这句话会被语音桥打破，必须改措辞；cloud provider 会让音频出本机。
4. **热键误触敏感内容**：靠「先看后交」档 + 5 秒撤销；不做启发式检测。
5. **与原生粘贴冲突**：焦点规则写错就会「打不出字」或「粘贴被吞」——本功能最容易回归处。
6. **首屏成本**：任何常驻语音入口都是本插件「低频收 `⋯`、首屏留列表」规矩的第一个例外。
7. **系统听写可能已覆盖**：若 `Win+H` 能在草稿框用，语音的增量几乎为零（待验证）。

## 10. 验收标准

**剪贴板**
- 从「内容已在剪贴板」到「便签已落盘」≤ 2 次操作；菜单档到「文本进草稿」= 1 次点击；

- 不新增 note 字段；备份/恢复兼容；300 条 perf 不变；`node scripts/check.mjs` 全绿（含反验）。

- 六种失败态各有说明与重试；只允许 host-local；音频不落任何存储；
- README 隐私承诺已改写；中英字典、aria、对比度不受影响。
