# 颜色能派生出什么？—— 三人视角汇总与裁决

> 三方独立调研（交互 / 工程 / 产品批判），各自全文见 [ux.md](ux.md)、[engineering.md](engineering.md)、[product-critic.md](product-critic.md)。
> 本文是 Lead 的汇总：保留分歧、给出裁决与分阶段路线。

## 一句话结论

**颜色今天在说谎**：新便签的颜色是**随机分配**的（`lib/client.js:1848`），但一列随机色条看起来就像有含义。
所以第一优先级不是「给颜色加语义」，而是**停止随机 + 让颜色可命名、可检索**；语义怎么做，等埋点数据说话。

## 现状（Lead 亲自核过代码）

| 事实 | 证据 |
| --- | --- |
| 颜色是单个字符串 id，五值 `amber/sky/mint/rose/violet` | `client.js:79`，非法值回落 amber `:93` |
| **新便签取色是随机的** | `:1848` `COLOR_IDS[Math.floor(Math.random()*5)]` |
| 只出现在两处：卡片 3px 左色条 + 右下 12px 色点 | `:2673`、`:2710` |
| 换色 = 点一下循环，`aria-label` 恒为「换个颜色」 | `:1924-1934`、`:1324` |
| 颜色不参与搜索 / 筛选 / 分组 / 统计；Markdown 导出丢颜色 | 搜索只匹配正文与 `#标签` |
| **没有「换色」埋点** | `METRIC_KEYS` 无 color（`:343`） |
| 五色 hex 对浅色卡片底 **1.73–2.76:1**，全部 < 3:1；深色 4.11–8.27 ✓ | 三人两套独立计算，Lead 按 WCAG 公式复算 amber = 1.73 一致 |
| sky/rose/violet 相对亮度 0.330/0.332/0.333，几乎相同 | 灰度/色觉模拟下只剩色相在区分 |
| 5 色 hex 不在 `test/contrast.mjs` 门禁里；换色交互 0 测试覆盖 | 改色不会有人拦 |

## 三方立场对照

| | 推荐 | 反对 | 最硬的一条证据 |
| --- | --- | --- | --- |
| 交互（ux-color） | C1 用户自定义分类色 + 具名调色板 + C3 颜色即检索；C2 时间褪色放 P2 | 产品写死语义、优先级色、状态/进度色、会话自动色、按色分组、扩到 8-12 色、整卡底色 | 颜色只活在「事后」（整理/回看），捕获路径没有它的位置；浅色对比度不达标 |
| 工程（eng-color） | A 纯视图层映射（代码内冻结表，数据不动，零迁移） | C 弱约定当方案；B 新增 `role` 字段（除非同色多义，且要先收口 7 处字段白名单） | 旧标签页不认新字段 + 300ms 整份写回 → 新字段会被静默吞掉；`parseBackup` 不校验 version |
| 产品批判（critic） | 全部「颜色=语义」都不值得；唯一凑合可做的是 S4「颜色随 `#标签` 派生」 | 5 色固定语义 + 图例（教育成本最高、与置顶/归档/#标签三重重叠） | 颜色不可搜、收起态不显示、没有图例位；用户要背 5 条字典且保证不过期 |

### 核心分歧：谁定义颜色含义？

1. **产品写死**（琥珀=待办、玫瑰=问题）——交互否、产品否、工程虽技术上最简单但语义不可迁移。**裁决：不做。**
2. **用户自定义**（我拿蓝色装工作）——Keep 用户确实这么干（[Yahoo](https://tech.yahoo.com/apps/articles/6-simple-google-keep-tweaks-190013323.html)、[Android Police](https://www.androidpolice.com/have-been-using-google-keep-for-years-and-wish-knew-about-these-tricks-sooner/)），纸笔便利贴的心智模型现成。**裁决：做，但只做「可命名 + 可检索」这两件，不做图例系统。**
3. **从 `#标签` 派生**（同标签同色，颜色成为标签的影子）——零字段零教育，但会覆盖用户手选色，且与「用户自定义」互斥。**裁决：作为 Plan B，由埋点数据决定。**

## 候选池与打分

成本：S ≤ 半天，M ≤ 1-2 天，L > 2 天。均以「不破坏随手记定位 / 不加常驻 UI」为前提。

| # | 方案 | 价值 | 成本 | 风险 | 裁决 |
| --- | --- | --- | --- | --- | --- |
| 1 | 停止随机默认色（固定 amber 或随标签派生） | 颜色不再假装有含义 | S | 老便签仍是随机色（可用导出+导入统一，或接受） | **做（P0）** |
| 2 | 色点 `aria-label` 带色名 + 换色后播报 | 读屏可感知；也是「可命名」的前提 | S | 播报太吵 → 只播一次 | **做（P0）** |
| 3 | 换色埋点（`METRIC_KEYS` 加 color） | 决定后续路线的唯一依据 | S | 无 | **做（P0）** |
| 4 | 浅色主题 5 色加深 + 纳入 contrast 门禁 | 修 1.73-2.76 的不达标；拉开明度差 | S | 老用户看到的色条变深 | **做（P0）** |
| 5 | 具名调色板（点色点弹出 5 色 + 色名，直接选色；循环保留为快捷） | 从「碰运气」变「我决定」；给分类色一个自解释的图例位 | M | 300px 里弹层要翻方向；新测试要补 | **做（P1）** |
| 6 | 颜色即检索（搜索框左侧色点触发器，显示各色条数） | 把「看见」变「查到」，且替代「图例」 | M | 与 `#标签` 两套筛子要定义「且」；筛选必须加在 `filteredNotes` 而非 `baseList` | **做（P1）** |
| 7 | 时间褪色（色相分类、明度表示新鲜度） | 零输入，服务回顾条 | S | 与手选色冲突；必须先做 4 | 观察后再定（P2） |
| 8 | 颜色随 `#标签` 派生 | 零字段零教育，把随机噪声换成标签影子 | S | 会覆盖手选色；与「用户自定义」互斥 | **Plan B（P2，看埋点）** |
| 9 | 新增 `role` 字段存语义 | 同色多义时最灵活 | M | 旧标签页写回会吞掉；7 处字段白名单要收口；备份 version 不校验 | 暂不做 |
| 10 | 产品写死 5 色语义 + 图例 | 无（用户要背字典） | S | 换语言/换团队即错；与置顶/归档/#标签重叠 | **不做** |
| 11 | 优先级色 / 状态色 / 会话自动色 / 按色分组 / 8-12 色 / 整卡底色 | 低或负 | - | 破坏随手记定位或违反 WCAG 1.4.1 | **不做** |

## 裁决：三段式路线

**P0「先别骗人」（S，约半天，可立刻做）**
1. 新便签默认色固定（不再随机）；
2. 色点 `aria-label` =「颜色：天蓝（点击更换）」，换色后一次温和播报；
3. `METRIC_KEYS` 加 `color`，换色时打点；
4. 浅色主题 5 色压一档明度（ux.md 3.6 给了建议值），并把 5 色纳入 `test/contrast.mjs`。

**P1「让颜色能当分类用」（M，1-2 天）**
5. 具名调色板：点色点弹出 5 个色块 + 色名，直接选；键盘 Enter 打开、方向键移动、Esc 关闭；循环换色保留为快捷路径；
6. 颜色即检索：搜索框左侧 20px 色点触发器，显示各色条数，选中后搜索框里出现「色：天蓝 ×」；与 `#标签` 是「且」；
7. 补两类测试：换色/调色板（现在 0 覆盖）、颜色筛选与搜索态叠加（防止只加在 `baseList` 被静默忽略）。

**P2「看数据决定」（S）**
- 埋点观察 1-2 周：
  - 若**换色率极低**（大多数便签从没人动过颜色）→ 说明颜色只是装饰，走 **Plan B（8）**：颜色由首个 `#标签` 派生，把随机噪声换成有意义，同时不新增任何 UI；
  - 若**换色率可观**（用户确实在分类）→ 继续加深 C1/C3（时间褪色 7 也可以上了）。

## 工程红线（做上面任何一项都必须遵守）

- **不要给 memo 卡片新增 prop**：实测每卡多 1 个稳定 prop 会让 300 条稳态从 0.30ms 涨到 0.63-0.67ms；颜色相关派生在卡片内部用已有的 `note.color` 算。
- **不要新增 `role` 字段**（除非同色多义）：7 处手写字段白名单漏一处就会被拖动/置顶/编辑洗掉；何况旧标签页整份写回会吞掉新字段，`parseBackup` 还不校验 `version`。
- **颜色筛选加在 `filteredNotes`**，不是 `baseList`——否则搜索态会绕过它，变成「搜索时颜色筛选静默失效」。
- 颜色一旦承载信息，必须有**非颜色冗余**（色名写进 aria-label / tooltip、筛选器带文字），否则违反 WCAG 1.4.1；浅色主题下这 5 个色值连 3:1 都不到。
- `scripts/check.mjs` 不跑 perf；改动碰渲染路径时手动跑 `node test/perf.mjs 300 60` 并记录数字。

## 需要你拍板的两件事

1. **颜色要不要有「官方含义」？** 我建议不要（用户自定义），只在调色板里给色名。若你希望「红=重要」这种预装语义，我们得先接受它和错误色、置顶语义打架的代价。
2. **P1 的两项是否一起做？** 调色板单独做会让「能选色但不能按色找」像个半成品；我建议 5+6 同批，一次做完再发版。
